# Руководство пользователя САОТ

«Система автоматизации охраны труда» (САОТ) — модульное веб-приложение для ведения реестров юридических лиц, контингента рабочих мест, поимённого учёта работников, кадровой истории перемещений, импорта/экспорта в Excel и обеспечения целостности данных по охране труда.

---

## 1. Запуск и перенос приложения

### 1.1 Требования к окружению
- **Node.js** версии 20 или 22 LTS;
- Современный веб-браузер (Google Chrome, Яндекс.Браузер, Mozilla Firefox, Microsoft Edge);
- Доступ к локальному порту (по умолчанию `3000`).

### 1.2 Команды запуска
```bash
# 1. Установка зависимостей (выполняется один раз)
npm install

# 2. Запуск в режиме разработки
npm run dev
# Приложение доступно по адресу: http://localhost:3000

# 3. Проверка типов и линтинг
npm run lint

# 4. Запуск автоматических тестов
npm test

# 5. Сборка для постоянной эксплуатации
npm run build
npm run preview
```

### 1.3 Перенос данных на другой компьютер
1. В исходном приложении перейдите в раздел **«Резервные копии»** и нажмите **«💾 Создать резервную копию (JSON)»** — скачается файл вида `saot_backup_YYYY-MM-DD...json`.
2. На целевом компьютере откройте САОТ, перейдите в раздел **«Резервные копии»** и нажмите **«📥 Восстановить из файла...»**.
3. Выберите сохранённый JSON-файл. Приложение автоматически создаст страховочную копию текущего состояния, развернёт данные и выполнит проверку ссылочной целостности (Сценарий 18).

## 2. Главная панель и выбор текущей организации

### 2.1 Индикатор «Текущая организация»
В верхней панели приложения (шапке) отображается бейдж текущей выбранной организации:
- Если организация не выбрана, отображается бейдж **«Организация: не выбрана»**;
- Нажав на бейдж или перейдя в карточку организации, можно нажать кнопку **«Выбрать как текущую»**;
- При выборе текущей организации все реестры (контингент, работники) автоматически фильтруются по ней.

### 2.2 Показатели главной панели
На главной панели отображаются виджеты с фактическими данными (без фиктивных счётчиков):
- Количество зарегистрированных юридических лиц;
- Количество позиций контингента;
- Количество учтённых работников;
- Реестр подключённых функциональных модулей системы.

## 3. Реестр юридических лиц

### 3.1 Добавление организации вручную
1. В верхнем меню выберите **«Юридические лица»** → нажмите **«+ Добавить организацию»**.
2. Заполните обязательное поле **Полное наименование** (например, `Общество с ограниченной ответственностью «Северный Металлург»`).
3. Заполните реквизиты:
   - **ИНН**: 10 цифр для юрлиц, 12 цифр для ИП. Система автоматически проверяет формат и официальную контрольную сумму;
   - **КПП**: 9 цифр (для юрлиц);
   - **ОГРН**: 13 цифр (ОГРН) или 15 цифр (ОГРНИП);
   - Адреса (юридический и фактический) и дополнительные сведения.
4. При сохранении срабатывает контроль дубликатов:
   - Совпадение активной пары **ИНН + КПП** или **ОГРН** вызывает ошибку 409 (запрет дубликата);
   - Похожее наименование выдаёт жёлтое предупреждение.

### 3.2 Карточка организации
В карточке отображаются:
- Все реквизиты и адреса;
- Быстрые переходы к подразделениям, позициям контингента и списку работников этой организации;
- Кнопка **«Выбрать как текущую»**;
- Кнопка **«В архив»**: архивирование переводит организацию в статус архивной без физического удаления и без разрыва связей с работниками и контингентом (правило D-009).

### 3.3 Импорт юридических лиц из Excel
1. В разделе «Юридические лица» нажмите **«Импорт из Excel»**.
2. Скачайте официальный шаблон `template_legal_entities.xlsx` по кнопке **«📥 Скачать шаблон»**.
3. Заполните таблицу и выберите файл в форме загрузки.
4. Выберите режим:
   - **Пропускать дубликаты** (добавляются только новые записи);
   - **Обновлять существующие** (по совпадению ИНН+КПП или ОГРН обновляются реквизиты).
5. Изучите таблицу предпросмотра: строки с ошибками подсвечены красным, с предупреждениями — жёлтым.
6. Нажмите **«Подтвердить импорт»** для применения изменений или **«Отмена»** для сброса без последствий.

## 4. Реестр контингента

Контингент определяет штатные позиции с точки зрения охраны труда: вредные производственные факторы, периодичность медосмотров и условия труда.

### 4.1 Создание позиции контингента
1. Откройте раздел **«Контингент»** → нажмите **«+ Новая запись контингента»**.
2. Выберите **Юридическое лицо** (подставляется текущее, если выбрано).
3. Укажите **Подразделение** (можно выбрать из существующих или добавить новое прямо из формы).
4. Укажите **Должность** (глобальный реестр должностей нормализует пробелы и регистр по правилу D-013).
5. Заполните параметры рабочего места:
   - Уточнение рабочего места (например, `Цех №1, линия упаковки`);
   - График работы и сменность;
   - Номер карты СОУТ и подкласс условий труда (1, 2, 3.1, 3.2, 3.3, 3.4, 4);
   - Номер карты оценки профессиональных рисков (ОПР);
   - Пункты Приказа Минздрава № 29н (медосмотры, через точку с запятой);
   - Пункты Приказа Минздрава № 342н (психиатрическое освидетельствование);
   - Группа по электробезопасности (I, II, III, IV, V).
6. Нажмите **«Сохранить»**.

### 4.2 Импорт и экспорт контингента
- **Шаблон импорта**: 14 колонок согласно `IMPORT_EXPORT.md` §4. Идентификация записей осуществляется по составному ключу D-004 `(Юрлицо + Подразделение + Должность + Рабочее место)`.
- **Экспорт**: в формате Excel `.xlsx` и CSV с кодировкой UTF-8 BOM. Все ячейки экранируются от формульных инъекций (`=`, `+`, `-`, `@`).

## 5. Поимённый список работников и кадровые перемещения

### 5.1 Добавление работника
1. Откройте раздел **«Работники»** → нажмите **«+ Добавить работника»**.
2. Укажите персональные данные:
   - Фамилия, Имя, Отчество;
   - Дата рождения (контроль: дата не может быть в будущем);
   - Дата приёма на работу (контроль: дата не может быть в будущем);
   - **СНИЛС**: ввод в формате `XXX-XXX-XXX YY`. Система вычисляет официальную контрольную сумму ПФР РФ с весовыми коэффициентами. Номера `<= 1001998` не подлежат проверке контрольной суммы.
3. Выберите подразделение, должность и запись контингента:
   - В выпадающем списке отображаются только позиции контингента **того же юридического лица**;
   - Автоматическая неявная привязка запрещена — выбор осуществляется исключительно явно пользователем (FR-09).
4. Проверка дубликатов:
   - Если в организации уже есть работник с таким СНИЛС, система выведет предупреждение о возможном совмещении, не блокируя сохранение;
   - Если совпадают ФИО и дата рождения, система предупредит о полном совпадении, напоминая о запрете автообъединения по ФИО.

### 5.2 Карточка работника и история перемещений (D-005)
В карточке работника представлены:
- Паспортные реквизиты, должность, СНИЛС и организация;
- Статус привязки к контингенту охраны труда со ссылкой на позицию;
- **Таблица истории кадровых перемещений**:
  - При каждом переводе (изменение подразделения, должности или привязки к контингенту) система автоматически фиксирует дату завершения предыдущего периода (`end_date`) и открывает новый период (`start_date = текущая дата`);
  - Пользователь указывает причину перевода (например, `Плановый перевод`, `Приём на работу`) и комментарий;
  - Прошлые периоды неизменяемы и сохраняются в истории;
- Журнал аудита всех действий с карточкой работника.

### 5.3 Импорт работников из Excel
1. В разделе «Работники» нажмите **«Импорт работников»**.
2. Скачайте шаблон `template_employees.xlsx` (10 колонок per `IMPORT_EXPORT.md` §5).
3. **Правило идентификации**: сопоставление выполняется строго по **СНИЛС + Юридическое лицо**.
4. Если СНИЛС в файле не указан, запись **ни в коем случае не объединяется** по ФИО, а создаётся как новый работник с предупреждением.
5. Перед выполнением импорта система автоматически создаёт точку восстановления базы данных.

## 6. Резервное копирование и проверка целостности

Раздел **«Резервные копии»** обеспечивает защиту данных от сбоев и ошибок пользователей.

### 6.1 Виды резервных копий
1. **Ручная копия**: создаётся по нажатию кнопки «💾 Создать резервную копию (JSON)» и скачивается на диск;
2. **Страховочная копия (`pre-restore`)**: создаётся автоматически перед каждым восстановлением данных из файла или снимка;
3. **Автоматическая копия перед импортом (`auto-import-*`)**: создаётся системой перед пакетной загрузкой юридических лиц, контингента или работников;
4. **Суточная автокопия (`auto-daily`)**: создаётся автоматически раз в 24 часа при открытии приложения.

### 6.2 Восстановление данных
- Восстановление можно выполнить из любого ранее сохранённого `.json` файла на компьютере либо выбрав снимок из таблицы истории;
- Любой снимок из таблицы можно скачать в виде отдельного JSON-файла по кнопке **«Скачать»**.

### 6.3 Проверка целостности данных (Сценарий 18)
В разделе доступна кнопка **«🔍 Проверить целостность данных»**:
- Проверяет все внешние связи (подразделения ссылаются на реальные юрлица; должности существуют; контингент и работники принадлежат той же организации);
- Проверяет отсутствие циклических связей в иерархии отделов;
- Проверяет корректность дат и хронологию кадровой истории перемещений;
- Выводит детальный отчёт: количество проверенных сущностей, список ошибок связности (красный) и предупреждений (жёлтый).
- При каждом восстановлении из копии проверка целостности выполняется автоматически!

---

## 7. Журнал аудита

Раздел **«Аудит»** фиксирует каждое значимое действие в системе:
- Тип действия: создание, изменение, перевод, архивирование, восстановление, импорт;
- Идентификатор и тип затронутой сущности;
- Снимки данных: состояние объекта **ДО** и **ПОСЛЕ** изменения в формате JSON;
- Дата, время и комментарий к операции.

---

## 8. Известные ограничения версии 1.0
- Приложение работает локально с хранением в браузере (LocalStorage); для переноса между ПК используется механизм резервного копирования JSON.
- Аутентификация пользователей и разграничение прав по ролям планируются в следующих релизах.
- Работа с макросами Excel `.xlsm` отключена из соображений информационной безопасности.
