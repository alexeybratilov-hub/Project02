# AGENT_GUIDE

Обязательная инструкция для любого ИИ-агента, которому передаётся проект.

## 1. Порядок действий

1. Прочитать `PROJECT_CONTEXT.md`.
2. Прочитать `HANDOFF.md`.
3. Изучить `ROADMAP.md` и `TASKS.md`.
4. При необходимости изучить `ARCHITECTURE.md`, `DATA_MODEL.md`, `DECISIONS.md`.
5. Проверить фактическую структуру репозитория.
6. Проверить состояние Git и незакоммиченные изменения, если Git используется.
7. Проверить, запускается ли проект, и определить состояние тестов.
8. Выбрать одну конкретную задачу текущего этапа.
9. Реализовать её без ненужного изменения остальных компонентов.
10. Провести проверки.
11. Обновить документацию.
12. Записать результаты в `HANDOFF.md`.
13. Указать следующую задачу.

## 2. Запреты

- не начинать реализацию, не ознакомившись с состоянием проекта;
- не создавать проект заново без доказанной необходимости;
- не заменять работающую архитектуру без причины;
- не удалять существующие функции без обоснования;
- не создавать дублирующие компоненты;
- не оставлять фиктивные кнопки;
- не утверждать, что тесты пройдены, если они не запускались;
- не коммитить секреты, реальные ПДн и рабочие базы;
- не выполнять разрушительные операции с БД без резервной копии и обоснования;
- не переписывать историю Git без необходимости.

## 3. Противоречия документации и кода

Если документация противоречит коду:

1. выявить противоречие;
2. проверить фактическое состояние;
3. исправить документацию или код в соответствии с согласованной архитектурой;
4. зафиксировать решение в `DECISIONS.md`, если оно значимо.

Нельзя автоматически считать любой источник правильным.

## 4. Definition of Done

Задача завершена, если:

- критерии приёмки выполнены;
- проверки проведены и зафиксированы;
- регрессии не обнаружены;
- документация обновлена;
- `HANDOFF.md` обновлён;
- следующая задача указана.

## 5. Если задачу выполнить невозможно

Не имитировать завершение. Зафиксировать:

- фактическое состояние;
- причину блокировки;
- изменённые файлы;
- результаты проверок;
- точку продолжения.

## 6. Стиль работы

- небольшие законченные этапы;
- сначала ядро, затем модули;
- сохранять работающую функциональность;
- использовать миграции;
- добавлять тесты;
- обновлять шаблоны импорта/экспорта при изменении полей;
- фиксировать отклонения от плана.
