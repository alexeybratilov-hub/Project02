# DECISIONS

Журнал архитектурных решений.

## D-000. Документация как часть Definition of Done

- **Статус:** принято.
- **Проблема:** разные ИИ-агенты теряют контекст и переписывают проект.
- **Решение:** документация обновляется на каждом этапе; этап не считается завершённым без неё.
- **Последствия:** больше времени на документы, меньше повторной разработки.

## D-001. Технологический стек

- **Статус:** **не утверждено**. Утвердить на этапе 0.
- **Проблема:** нужен стек для Windows-портативности, локальной БД, Excel, модульности и серверного развёртывания.
- **Кандидаты:**
  - A: Python + FastAPI + SQLAlchemy/Alembic + SQLite/PostgreSQL + React/Vite + openpyxl;
  - B: Node.js + NestJS + Prisma + SQLite/PostgreSQL + React + exceljs;
  - C: .NET 8 + EF Core + SQLite/PostgreSQL + React или Blazor + ClosedXML.
- **Критерии:** упаковка под Windows, Excel, миграции, скорость разработки с ИИ, серверное развёртывание, поддерживаемость одним человеком.
- **Предварительная рекомендация:** A или C; окончательно утвердить после проверки упаковки.
- **Последствия:** после утверждения менять стек только при доказанной технической необходимости.

## D-002. СУБД

- **Статус:** **не утверждено**.
- **Проблема:** нужна локальная переносимая БД и путь к серверной.
- **Кандидаты:** SQLite (WAL) для локальной версии; PostgreSQL для серверной.
- **Критерии:** целостность, миграции, резервное копирование, многопользовательский режим, переносимость.
- **Предварительная рекомендация:** SQLite для v1 с абстракцией доступа к данным и поддержкой PostgreSQL в перспективе.
- **Последствия:** ограничения SQLite при многопользовательской работе должны быть зафиксированы.

## D-003. Упаковка под Windows

- **Статус:** **не утверждено**.
- **Проблема:** запуск из папки не означает отсутствие зависимостей.
- **Кандидаты:** embedded runtime + launcher; single-file executable; portable runtime + .bat; installer.
- **Критерии:** запуск одним действием, отсутствие ручной установки, обновляемость, резервное копирование.
- **Предварительная рекомендация:** портативная папка с встроенным runtime и launcher; installer — позднее.
- **Последствия:** влияет на структуру папки и инструкцию запуска.

## D-004. Идентификация записи контингента

- **Статус:** **не утверждено**.
- **Проблема:** от идентификации зависит связь работников и наследование требований.
- **Кандидаты:**
  - A: юридическое лицо + подразделение + должность + рабочее место;
  - B: A + набор ключевых условий;
  - C: отдельная сущность «рабочее место».
- **Предварительная рекомендация:** B для v1 с путём к C.
- **Последствия:** влияет на уникальные ограничения, импорт и связи.

## D-005. История переводов работников

- **Статус:** **не утверждено**.
- **Проблема:** нужно ли хранить историю изменений подразделения/должности/контингента.
- **Кандидаты:** без истории в v1; таблица истории; полная версионность карточки.
- **Предварительная рекомендация:** таблица истории с датами и причиной.
- **Последствия:** влияет на модель данных и отчёты.

## D-006. Стратегия обновления и миграций

- **Статус:** **не утверждено**.
- **Проблема:** обновление не должно ломать данные.
- **Кандидаты:** forward-only миграции + обязательная копия; автоматические миграции при старте; отдельная команда обновления.
- **Предварительная рекомендация:** forward-only, обязательная копия, подтверждение перед применением.
- **Последствия:** влияет на запуск, резервное копирование и инструкцию обновления.

## D-007. СНИЛС хранится строкой

- **Статус:** принято.
- **Причина:** сохранение формата и ведущих нулей.
- **Последствия:** валидация формата на уровне приложения.

## D-008. Браузерное хранилище не является единственным постоянным хранилищем

- **Статус:** принято.
- **Причина:** риск потери данных при очистке браузера.
- **Последствия:** постоянное хранилище — БД на диске.

## D-009. Архивирование вместо каскадного удаления

- **Статус:** принято.
- **Причина:** сохранение истории и связей.
- **Последствия:** статусы, фильтры, запрет жёсткого удаления связанных записей.

## D-010. Импорт с предпросмотром и транзакцией

- **Статус:** принято.
- **Причина:** предотвращение частичного повреждения данных.
- **Последствия:** обязательные этапы проверки и отчёт.

## D-011. Модульный монолит

- **Статус:** принято.
- **Причина:** сложность микросервисов не оправдана для одного специалиста.
- **Последствия:** единый процесс, общая БД, границы модулей на уровне кода.

## D-012. Тип внутренних идентификаторов

- **Статус:** предложено, не утверждено.
- **Кандидаты:** UUID; целочисленные surrogate-ключи.
- **Предварительная рекомендация:** UUID для переносимости и объединения данных.
- **Последствия:** влияет на размер индексов и отображение.

## D-013. Область действия справочника должностей

- **Статус:** предложено, не утверждено.
- **Кандидаты:** глобальный справочник; справочник в рамках юридического лица.
- **Предварительная рекомендация:** глобальный с возможностью расширения.
- **Последствия:** влияет на уникальность и импорт.

## D-014. JSON в журнале аудита

- **Статус:** принято.
- **Причина:** снимки до/после удобно хранить в JSON.
- **Ограничение:** JSON не используется вместо основной структуры данных.

## D-015. Документация — часть критериев завершения этапа

- **Статус:** принято.
- **Последствия:** этап без обновления документации считается незавершённым.
