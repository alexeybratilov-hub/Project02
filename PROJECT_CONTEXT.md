# PROJECT_CONTEXT

Главный документ для передачи проекта между ИИ-агентами. Отражает фактическое состояние, а не только планы.

## 1. Назначение проекта

Собственное модульное веб-приложение для автоматизации работы специалиста по охране труда в РФ. Первая версия — переносимое приложение для Windows с локальной базой, ведением нескольких юридических лиц, реестром контингента и поимённым списком работников, импортом/экспортом Excel и резервным копированием.

## 2. Основные требования (кратко)

- несколько юридических лиц в одной базе;
- единая модель данных и связанные справочники;
- отсутствие дублирования одного факта в разных местах;
- реестр контингента с 12 первоначальными полями;
- поимённый список работников;
- импорт Excel с предпросмотром, проверками и отчётом;
- экспорт Excel без потерь;
- история изменений (базовый журнал);
- резервное копирование и восстановление;
- модульность и расширяемость;
- русскоязычный интерфейс;
- работа без обязательного облака.

Полные требования — `PRODUCT_REQUIREMENTS.md`.

## 3. Технологический стек

**Статус: УТВЕРЖДЁН (D-001, 2026-10-22).**

Python 3.12 + FastAPI + Uvicorn + SQLAlchemy 2.x ORM + Alembic (миграции) + SQLite WAL (путь к PostgreSQL — D-016) + openpyxl (Excel) + Jinja2 (серверные HTML-страницы вместо SPA) + Pydantic v2 + pytest. Версии зафиксированы в `requirements.txt`. Обоснование и отвергнутые альтернативы — `DECISIONS.md` D-001…D-003.
