# Система автоматизации охраны труда (САОТ)

Модульное веб-приложение для автоматизации работы специалиста по охране труда в Российской Федерации. Проект разрабатывается итеративно разными ИИ-агентами; документация является частью проекта и обновляется по фактическому состоянию.

## Текущее состояние

**Стадия: 0 — проектирование. Код приложения не реализован.**

В репозитории присутствует только комплект проектной документации. Пользовательские сценарии пока не работают. Не используйте репозиторий как готовое приложение.

## Назначение

- ведение нескольких юридических лиц в одной базе;
- единая система связанных справочников и реестров;
- реестр контингента работников;
- поимённый список работников;
- импорт и экспорт Excel с предварительной проверкой;
- резервное копирование и восстановление;
- подключение функциональных модулей без переписывания ядра.

## Целевая среда

- Windows 10/11, запуск из папки проекта;
- браузер Chrome/Edge актуальной версии;
- локальное хранение данных без обязательного облака;
- возможность последующего развёртывания на локальном сервере.

Стек утверждён на этапе 0 (D-001, 2026-10-22): Python 3.12 + FastAPI + Uvicorn + SQLAlchemy 2.x + Alembic + SQLite (WAL) + openpyxl + Jinja2 + Pydantic v2 + pytest. СУБД — SQLite (D-002), упаковка под Windows — portable embedded Python + start.bat/stop.bat (D-003). Подробности — `DECISIONS.md` (D-001…D-006, D-012, D-013, D-016) и `ARCHITECTURE.md` §13–14; версии зависимостей зафиксированы в `requirements.txt`.

## Структура папки проекта (утверждена, создаётся на этапе 1)

```text
/app            — код приложения (core, modules, templates, static, alembic)
/data           — рабочая база данных (saot.db, SQLite WAL)
/attachments    — связанные файлы
/backups        — резервные копии
/logs           — технические журналы
/runtime        — embedded Python (portable-упаковка Windows, D-003)
/prompts        — мастер-промпт и задания по этапам
*.md            — проектная документация (в корне репозитория)
```

Рабочие папки `data/`, `attachments/`, `backups/`, `logs/` создаются приложением автоматически (T1-02) и исключены из Git через `.gitignore` (появится на этапе 1).

## Данные и резервные копии

Рабочая база — `data/saot.db` (SQLite, режим WAL, D-002); резервные копии — `backups/`, журналы — `logs/`. Пути определяются конфигурацией (`SAOT_DB_URL` и переменные окружения, T1-02). Требование: рабочие данные, персональные данные и резервные копии не попадают в Git.

## Обновление и восстановление

Стратегия утверждена на этапе 0 (D-006): миграции Alembic только вперёд (forward-only), перед применением миграций — обязательная автоматическая резервная копия; откат — восстановлением из копии. Реализация — этап 1 (T1-04, T1-09). Требования к резервному копированию — в `SECURITY.md` и `TESTING.md`.
